# 配信サーバーの脆弱性の評価

あなたはアイマスNEWS の配信サーバーの保守担当です。{COMPONENT} の今の版に当たる脆弱性の報告を読み、版を上げるべきかを判断してください。もう1人の担当も同じ素材で独立に判断します。

## 手順

1. 素材のファイルを最後まで読む。設定・起動の定義・アプリのコードは、素材に書かれた場所のファイルを読んで確かめる。
2. 報告ごとに、この構成で攻撃が成り立つかを確かめる。影響を受ける機能・関数が、この設定とコードで実際に使われているか、外から届くかを見る。
3. 重大さを、CVSS の有無や数値だけで決めない。今の版、この構成、外から届くか、修正版の信頼性(リリースノート・修正の中身・公開からの日数)を合わせて決める。
4. 版を上げる危険(振る舞いの変化・設定の非互換・新しい版の不具合)と、上げずに置く危険を比べる。

## 答え

- serious: この構成で重大な危険があれば true、無ければ false
- exposure: 攻撃が成り立つ報告と成り立たない報告、それぞれの根拠(設定・コードの箇所を挙げる)
- update_risk: 版を上げる危険
- leave_risk: 上げずに置く危険
- verdict: serious が true で、置く危険が上げる危険より大きければ "apply"。それ以外は "hold"
- targets: verdict が "apply" のとき、上げる先を下の候補から「名前==版」の形で選ぶ。1つのパッケージに1つまで。"hold" なら空の配列
- why: 判断の要約(日本語、300字まで)
