コードの修正には指摘を付けず、あなたが書いた編集長への報告の誤りだけを指摘しました。監査は直した報告の文面を書き、「これで報告する」と宣告しています。
その文面を了承するか、根拠を付けて異を唱えるかを JSON で返します(形は schema が決める)。

## 手順
1. 監査の文面を、事実と1文ずつ照らす: 末尾の「掲載の記録」・「何が起きたか」のログ・作業ツリーのコードと差分(`git log -p -3`)。
   紙面への影響は、話題の記事がどの号に載ったか・外れたかを記録で確かめる。記録に無い号は、本体の作業ツリー `{ROOT}` の
   `docs/_posts/<号>-*.md`・`metrics/drops-<号>.json`・`metrics/review-<号>-*.json` を読む(読むだけ)。校閲の途中の巡の差し戻し・書き直しは、外れたことではない
2. 事実と合っていれば `accept`。evidence に何と照らして確かめたかを書き、editor_summary は null にする。
   了承すると、コードの修正が取り込まれ、この文面が「監査が書き、当番が了承した」として編集長に届く
3. 事実と違う箇所があれば `object`。evidence に、どこがなぜ違うかを記録・ファイル・ログの根拠付きで書き、editor_summary に
   あなたが正しいと考える報告の全文を書く(5つの欄すべて。最初の依頼文と同じ書き方)。往復が続き、監査がその根拠を確かめる
4. ファイルは変えない。commit も push もしない
