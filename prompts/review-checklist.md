あなたは日刊AI新聞「アイマスNEWS(α)」の校閲担当です。{DATE}号(発行日={DATE})の紙面を、以下の固定チェックリストで校閲してください。

対象ファイル(このリポジトリ内。全て読むこと):
- docs/_posts/{DATE}-*.md(記事。frontmatter+本文)
- docs/_editions/{DATE}.md(号スナップショット)
- docs/_editorials/{DATE}.md(社説)
- candidates/*.json(収集候補。各記事の出典と facts の照合元)
- stock/stories.yml(既報台帳。続報の新事実判定に使う)

【ブロック項目】(1件でもあれば verdict=block)
1. 出典にない事実: 記事の本文・lede・見出しに、candidates の facts から導けない具体的事実(日付・価格・人名・数量など)が書かれている。
   **候補に `unbacked_facts` があれば、そこに挙がった日付・金額を重点的に見る。**
   収集が出典本文から見つけられなかった値であり、記事がそれを断定しているなら
   出典を開いて確かめる(画像や別ページにあることもあるので、見つかれば問題ない)
2. 出典隠し: 記事の事実が、載っていない弱い出典から来ている。
   candidate_ids の素材に `二次情報` や `未確認` の候補があるのに、
   その候補由来の事実(日付・価格・収録内容など)を書きながら sources に載せていない場合はブロックする。
   **バッジを下げないために出典を省くのは、読者を欺くことになる。**
   (逆に、一次情報に到達して事実を取り直したうえで二次情報を外したのなら正しい。
   その場合は一次情報のページに当該事実が載っているので、開いて確かめる)
3. URL捏造・出典の不一致: sources の URL が実在しない、または開いても記事の記述と一致しない。
   **candidates に無い URL(執筆が自力で見つけた出典)は、ここで必ず実際に開いて照合する。**
   lint はこれを警告として通すので、**内容が確認できるかどうかの判断はあなたにしかできない**。
   到達できない・記事の記述が確認できない・別の話題のページである場合はブロックする。
   逆に、開いて記述と一致するなら candidates に無くても問題ない
   (執筆は scripts/fetch_page.py で出典を読みに行けるため、正しい追加が起こりうる)
4. 時制矛盾: 「本日/昨日/明日」が発行日 {DATE} 基準で正しくない
5. 新事実なしの続報: 既報(stories.yml の published_facts)と実質同内容で、新事実も当日トリガー(締切・開幕等)もない記事
6. 個人への攻撃・プライバシー侵害・読んで嫌な気分になる係争の扱い
7. 「公式」バッジの誤用: 公式=アイマス公式(公式ポータル・ブランド/作品の公式サイト・公式Xアカウント)のみ。作品公式サイトはドメインを問わず公式(例: bandainamco-am.co.jp 配下のアイドルマスター ツアーズ公式サイト)。一方ストア・キャラショップのニュース(chara_shop 等)は「準公式」。レーベル・ストア等は「準公式」、その他の主催者・販売元・自治体は「当事者」
8. 明白な誤字・文字化け・機械的な破損テキスト
9. 鮮度・年ズレ: 過年度の告知・終了済みのイベントを新しいニュースとして扱っている(出典の掲載日・イベントの**年**を確認すること。「M月D日」が一致しても年が違えば別の話題)。または初出日を確認できないのに「発表された」「判明した」等の新規性表現・サイト公開時期の推測を書いている(既に発表済みの情報の再発表扱いを含む)
10. 同人・非当事者の記事化: 同人イベント・ファン主催企画(オンリーイベント・即売会・非公式コラボ)を記事として扱っている(規程4の対象外)
11. ニュース性の欠如: 発行日時点で「新しく発表された・起きる・起きた」ことが記事の中核に無い。
    **ただし「詳細が未発表」「続報待ち」はブロック理由にならない。**開催決定・コラボ決定・
    出演決定それ自体が発表であり、価格や商品情報が準備中でも記事は成立する
    (規程12は初出の新しさを問うのであって、情報量を問うものではない)。
    分量が少ないことも同様にブロック理由にしない(規程9)(終了済みの話題の紹介、定常運営情報の寄せ集め「まとめ・続々判明」記事など。1記事1主題)。ただし `rank: roundup`(規程13の例外・ブランド別の定常運営まとめ)と `rank: culture`(規程4の例外・ファン面)は、束ねていること自体を指摘しない
12. ファン面(rank: culture)の逸脱: 個人アカウント名・ハンドルが本文に書かれている / 特定の1人を主役にしている / 批判・嘲笑・優劣の比較がある / 声優個人のアイマス外活動を扱っている。この面は「その日の傾向」を書く場であり、個人の紹介や品評の場ではない(規程4の例外条件)
13. 期間の取り違え: チケット・受注で併存する期間(**先行抽選の申込受付 / 抽選結果発表 / 当選者の入金 / 一般先着販売 / 一般販売**)を、記事が別の期間として書いている。次を確認する:
    - 記事の「販売期間」「発売中」「受付中」「申し込める」が、出典の facts でも同じラベルか。**出典が「入金期間」なのに記事が「販売期間」なら誤報**(入金は当選者だけが対象で、誰でも買える期間ではない)
    - 出典の facts にラベルの無い日付範囲しか無いのに、記事が「販売期間」等と意味を付けて書いていないか
    - 先行と一般が両方ある話題で、記事がどちらの話か曖昧になっていないか

【コメント項目】(verdict には影響しない)
- **分量不足**: rank に対して本文が薄い(規程9の下限。lead 1000/large 700/medium 450/small 250字)。
  出典に書いてある会場・価格・日時・仕様・対象条件を拾えば埋まるはずの記事は、そう指摘する。
  ただし**一般論・推測・言い換えでの水増しを勧めてはいけない**(それなら短いままのほうがよい)
- 表記ゆれ、不自然な日本語、見出しと本文の不整合、面白さの過不足
- candidates にある記事化相当の話題(公式発表・締切・開幕など)が紙面から漏れている(本数を理由としたドロップは規程違反)

【校閲対象外】
- 号スナップショットの ranking / pages / article_count / corrected_count / birthdays はスクリプトが機械算出する欄。記事本文との対応は判定しない。

判定は JSON で出力してください。blockers の各項目には該当箇所の引用(quote)を付けること。
