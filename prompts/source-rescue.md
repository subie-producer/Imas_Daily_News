## 1. 手順
1. 下の「4. 素材」を読み、記事の中核の事実(内容・日付・期限・価格)を告知した出所を挙げる: 公式サイト・公式ポータル・ゲーム内お知らせのページ・公式 X・販売元・主催・出演者(当事者)・報道
2. WebSearch と `python3 scripts/fetch_page.py <URL>` で、その告知のページを探して開く。素材の二次情報が引用・リンクしている告知もたどる
3. 中核の事実が本文にあるページを page にする。見つけたが取得できなかったページ(HTTP 429・メンテナンス・描画の失敗)も page にし、why に取得できなかった応答を書く
4. 公式 X の投稿でしか告知されていない事実、ページが読めない事実は、X の原本を探す問い(x)にする。問いには、アカウント・投稿の時期・投稿の中身の手がかり(企画名・商品名・日付)を書く
5. 公式が関わるコラボ・商品・催しは、販売元・主催のページと投稿のほかに、作品の公式(公式サイト・公式 X・公式ポータル)の告知か、それを報じた報道も当たりに入れる。問い(x)の1つは作品の公式アカウントの投稿を探す問いにする
6. 下の「2. 答えの形」の JSON 配列だけを答える

## 2. 答えの形
```
[{"kind": "page", "url": "https://...", "why": "このページで確かめられる事実(取得できなかったなら、その応答)"},
 {"kind": "x", "question": "X で探す原本の投稿", "why": "なぜ X の原本が要るか"}]
```
- page は多くて {MAX_PAGES} 件、x は多くて {MAX_ASKS} 件。中核の事実に届くものから順に書く
- 当たりが1つも無ければ `[]`

## 3. やらないこと
- 素材にも開いたページにも無い URL を組み立てない
- まとめサイト・攻略サイト・ファンの投稿・素材と同じ二次情報を page にしない
- 事実を答えに書かない(事実は後段が page と X の原本から起こして確かめる)
